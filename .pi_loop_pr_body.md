# main/pppYmMegaBirthShpTail2: recover get_rand helper and inline temps for O0 shape (100.000 -> 100.000)

## What changed

`src/pppYmMegaBirthShpTail2.cpp` — four O0 shape recoveries, all O4 100% preserving:

* **birth O0 4304 -> 3712 (-592) via `get_rand` helper**: Original debug MAP lists `get_rand__Fv` 56B in `pppYmMegaBirthShpTail2.o`. The decompiled source called `Math.RandF()` directly at ~30 sites. At O0 with `-inline off` the retail calls a local `static inline float get_rand(){ float r=Math.RandF(); return r; }` (56B) and `birth` contains only `BL get_rand` per site; our direct `Math.RandF()` calls include the `Math` global load at each site, inflating birth. Replacing all `Math.RandF()` in `birth` with the helper moves that load into the helper body; `birth` shrinks 4304->3712 and `get_rand` now emits exact 56/56.
* **birth O0 3712 -> 3664 (-48) via Vec temp elision**: `Vec velocity = particleData->m_direction; pppScaleVectorXYZ(dst, velocity, s)` and similar `Vec velocity = m_position; pppNormalize(dir, velocity)` copy a Vec at O0 (3× lfs/stfs, 24B each). Retail passes source Vec directly.
* **render O0 1920 -> 2160 (+232) via inlining U8ToF32 + 8 via int temp**: Retail inlines the u8->f32 colour conversion (`dst.x=src[0]` etc. ×2) while our source called the weak `U8ToF32` helper (helper 140B separate). Inlining recovers 232B toward MAP's 2504. Additionally retail does `int _c = count-1; countMinusOne=(float)_c;` rather than direct cast; splitting adds 8B. Combined render 1920->2160 (-584->-344).

Remaining O0 deltas are `birth +404`, `render -344`, `calc +8`, `calc_particle -4`, `frame -16`, plus 2 MAP-only helpers (`get_noise` 136 UNUSED and `U8ToF32` 140 now inlined). Baseline total |delta| 1656 -> after 1060 (exact-count 5/10 -> 6/11).

## Why this is plausible original source, not compiler coaxing

* `get_rand` is not a size hack: EN debug MAP explicitly lists `get_rand__Fv` 56B in this object (also in `pppYmMegaBirthShpTail3`, `pppRyjMegaBirth`, `pppRyjMegaBirthModel`, `pppBreathModel`, `pppYmBreath`), and sibling Ryj sources define it identically with the `float r` local that matches 56B (first `return Math.RandF()` attempt was 32B, missing the local).
* Vec copy elision matches retail Ghidra `8008bb28` which shows `pppScaleVectorXYZ(..., particleData->m_direction, scale)` directly without a `local_xxx` Vec temp; previous `Vec velocity=` was decompiler invention.
* Inlining `U8ToF32` matches retail's `pppRender` which does `colorStart.x = src[0]` etc.; the weak `U8ToF32` helper exists as weak copy but render does not call it — O0 helper not emitted after inlining is expected, O4 still folds both forms identically.
* Int temp for `count-1` matches Ghidra `8008acc4` which shows `local_1c0 = 0x43300000; ... int _c = count-1; countMinusOne = (float)_c;` double-bias pattern at O0.
